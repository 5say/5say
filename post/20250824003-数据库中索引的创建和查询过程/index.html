一、索引创建过程

以 B+ 树索引 为例（MySQL InnoDB 默认索引类型）：

  1. 定义索引
CREATE INDEX idx_user_name ON user(name);
  • MySQL 会在数据表中创建一个 B+ 树结构，节点存储键值和对应的主键或行指针。
  1. 构建 B+ 树
  • 叶子节点：存储索引列 + 指向表行的指针（主键索引是聚簇索引，叶子节点存储完整行）
  • 非叶子节点：存储键值范围，用于快速查找
  • 排序插入：索引按键值大小排序，保证查找是 O(logN)
  1. 维护索引
  • 插入数据 → B+ 树自动平衡，分裂节点
  • 删除数据 → 合并节点，保持树平衡
  • 更新索引列 → 相当于删除 + 插入

🔑 特点：

  • 聚簇索引（主键）叶子节点存整行
  • 辅助索引（非主键）叶子节点存索引列 + 主键，用于回表

二、索引查询过程

1️⃣ 查询带索引的 SQL 

SELECT * FROM user WHERE name='Alice';

2️⃣ 执行流程

  1. MySQL 查询优化器
    • 判断是否存在可用索引
    • 生成执行计划（选择索引、扫描方式）
  2. B+ 树索引查找
    • 从根节点开始，比较键值
    • 按范围选择子节点 → 下一个节点
    • 到达叶子节点 → 找到索引值对应的行指针或主键
  3. 回表（若非聚簇索引）
    • 如果是非主键索引（辅助索引），通过叶子节点的主键找到完整行数据
  4. 返回结果

三、查询原理示意（B+ 树） 

根节点
 ├─ key1 -> 子节点1
 ├─ key2 -> 子节点2
 └─ key3 -> 子节点3
...
叶子节点
 ├─ Alice -> row_id=101
 ├─ Bob   -> row_id=102
 └─ Carol -> row_id=103
  • 查询 'Alice' → 根节点找 key1/key2/key3 → 走到叶子节点 → 找到行指针
  • 回表取完整行数据（辅助索引），或直接取叶子节点（聚簇索引）

四、优化原理

  1. 减少扫描行数
    • 全表扫描 O(N) → B+ 树查找 O(logN)
  2. 减少 IO
    • 每次只读取树节点页（通常 4~16 KB）
    • 叶子节点连续 → 顺序 IO 优化
  3. 提高排序/范围查询效率
    • B+ 树叶子节点有序 → ORDER BY / GROUP BY 可以直接走索引
  4. 覆盖索引避免回表
    • 查询字段都在索引中 → 直接从叶子节点返回结果

五、总结

阶段 过程
创建 建 B+ 树，排序、平衡、维护节点
插入/更新 分裂/合并节点，保持平衡
查询 优化器选择索引 → 根节点到叶子节点查找 → 回表（如需） → 返回结果
原理 减少扫描行数（O(logN)）、减少 IO、加速排序和范围查询
