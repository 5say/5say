内部类就是定义在另一个类内部的类，它和外部类有很强的关联性。它可以访问外部类的私有成员，通常用于实现逻辑上的组合关系或更紧密的封装。

一、Java 内部类的分类

1.1 成员内部类（Member Inner Class）

定义在类中，但不在任何方法中。

public class Outer {
    private String msg = "Hello";

    class Inner {
        void print() {
            System.out.println(msg); // 访问外部类的私有成员
        }
    }
}

特点：

  • 编译后的文件为：Outer$Inner.class

  • 可以访问外部类的所有成员（包括 private）。

  • 需要依赖外部类对象来创建：

    Outer outer = new Outer();
Outer.Inner inner = outer.new Inner();

1.2 静态内部类（Static Nested Class）

使用 static 修饰的内部类。

public class Outer {
    static class Inner {
        void print() {
            System.out.println("Static Inner");
        }
    }
}

特点：

  • 编译后的文件为：Outer$StaticInner.class

  • 不依赖外部类对象，可以直接创建实例。

  • 通常用于实现 Builder 模式。

  • 只能访问外部类的静态成员。

    Outer.Inner inner = new Outer.Inner();

1.3 局部内部类（Local Inner Class）

定义在方法中的内部类，只能在方法内部使用。

public class Outer {
    void method() {
        class Inner {
            void print() {
                System.out.println("Local Inner");
            }
        }
        Inner inner = new Inner();
        inner.print();
    }
}

特点：

  • 编译后的文件为：Outer$1LocalInner.class
  • 不能用 public、private、protected 修饰。
  • 如果访问外部方法的局部变量，该变量必须是 final 或 effectively final（Java8以后）。

1.4 匿名内部类（Anonymous Inner Class）

没有名字的类，通常用于快速实现接口或抽象类的一个实例。

Runnable r = new Runnable() {
    @Override
    public void run() {
        System.out.println("Running...");
    }
};

特点：

  • 编译后的文件为：Outer$1.class, Outer$2.class（数字代表声明顺序）`
  • 常用于回调、事件处理、线程。
  • 无法创建构造函数。
  • 只能使用一次（不可复用）。

二、内部类加载行为

内部类类型 编译文件 是否依赖外部类实例 是否独立加载 加载时机 类加载器行为
成员内部类 Outer$Inner.class ✅ 是 ✅ 是 创建内部类对象时 通过外部类类加载器加载 $ 文件
静态内部类 Outer$StaticInner.class ❌ 否 ✅ 是 访问类或创建实例时 与外部类一样由同一类加载器加载
局部内部类 Outer$1LocalInner.class ✅ 是 ✅ 是 方法运行到定义点时 同外部类加载器，可能延迟加载
匿名内部类 Outer$1.class 等 ✅ 是 ✅ 是 定义并创建实例时 编译时生成 $1.class，运行时加载

✅ 补充说明：

  • 内部类与外部类是 编译时绑定、运行时分开加载。
  • JVM 不会因为加载了 Outer.class 就同时加载 Outer$Inner.class，只有在使用到内部类时才会加载它。
  • 内部类会隐式持有外部类的引用（除非是静态内部类）。
  • 静态内部类不持有外部类引用，所以可以延迟加载。
  • 匿名内部类和局部类虽然写在方法里，但类信息在编译期就确定了，只是加载时机晚于成员类。
  • 如果你使用了反射或序列化，内部类和外部类可能有更复杂的依赖关系，要注意构造函数携带外部类引用的问题。
