JVM 加载一个类的过程，也叫做类加载机制，是 Java 程序运行的基础。它将 .class 字节码文件加载到 JVM 内存，并完成验证、解析和初始化等过程，最终让类可以被使用。

一、JVM 加载一个类的完整过程（五个阶段）

1.1 加载（Loading）

⏱ JVM 使用类加载器（ClassLoader）将 .class 文件读入内存，生成 Class 对象。

常见类加载器：

  • Bootstrap ClassLoader（启动类加载器，加载 JDK 核心类）
  • Extension ClassLoader（扩展类加载器）
  • App ClassLoader（系统类加载器）
  • 自定义 ClassLoader

1.2 验证（Verification）

⛔ 确保字节码文件格式正确、安全无害。

主要验证内容：

  • 文件格式验证（magic number等）
  • 元数据验证（类继承是否合理）
  • 字节码验证（是否非法跳转、越界）
  • 符号引用验证（是否能成功解析）

1.3 准备（Preparation）

📦 为类的静态变量分配内存并设置为默认值。

注意：此时不会执行任何初始化代码！

static int a = 10;

此阶段：

  • 只会为 a 分配空间，赋值为 0
  • 赋值为 10 是初始化阶段才做的事

1.4 解析（Resolution）

🔧 将常量池中的**符号引用（符号名）*转换为*直接引用（地址或指针）

比如将：

invokevirtual #5 // Method java/lang/Object.toString:()Ljava/lang/String;

解析为在虚方法表中的实际地址。

1.5 初始化（Initialization）

🚀 真正执行类的 <clinit> 方法（由静态变量赋值 + 静态代码块组成）

static int a = 10;
static { System.out.println("初始化类"); }

特点：

  • 初始化是多线程同步的（同一个类只会初始化一次）
  • 父类会在子类初始化前初始化

二、JVM 类加载时机（什么时候触发？）

✅ 主动使用（会触发类加载）：

触发场景 示例代码
创建类实例 new MyClass()
访问类的静态变量 MyClass.value
调用类的静态方法 MyClass.staticMethod()
反射调用类 Class.forName("MyClass")
子类初始化时，父类也要初始化 new SubClass()
JVM 启动时加载主类 public static void main(...)

❌ 被动使用（不会触发类加载）：

  1. 访问静态常量（final static）时被编译器内联
  2. 创建数组（但不加载类）
  3. 引用类的 Class 对象不会触发初始化

示例：

System.out.println(SomeClass.CONSTANT); // 不触发加载
SomeClass[] array = new SomeClass[10]; // 也不会

三、类加载机制的高级特性

3.1 双亲委派模型（Parent Delegation Model）

类加载器加载类时，先委托父加载器加载，如果父亲无法加载，才自己尝试加载。

优点：

  • 避免重复加载
  • 保证核心类不被篡改（如 String、Object）

3.2 热加载与卸载

  • JVM 不支持类的主动卸载（除非类加载器被回收）
  • 可以使用自定义 ClassLoader + 反射实现热部署（如 Spring、Tomcat）

四、完整的一个类的生命周期 

         编译后 -> MyClass.class
                       ↓
                  【加载 Load】
                       ↓
                 【验证 Verify】
                       ↓
                 【准备 Prepare】
                       ↓
                 【解析 Resolve】
                       ↓
               【初始化 Initialize】
                       ↓
                   【使用 use】
                       ↓
                【卸载 uninstall】

五、类加载器的分类与职责

5.1 JVM内置类加载器

加载器名称 作用 加载内容
Bootstrap ClassLoader 启动类加载器（JVM 内部 C++ 实现） 加载 rt.jar 中的核心类（java.lang.* 等）
Extension ClassLoader 扩展类加载器 加载 JAVA_HOME/lib/ext 或 java.ext.dirs 下的类
App ClassLoader 应用类加载器（默认加载器） 加载 classpath 中的类（开发者编写的类）

这些加载器遵循 双亲委派机制，即：一个类加载请求总是先由父加载器处理，如果父加载器无法加载，才由当前加载器处理。

双亲委派机制是 Java 类加载器的一种安全机制，防止核心类被恶意篡改。

加载流程如下：

text复制编辑AppClassLoader
    ↓
ExtClassLoader
    ↓
Bootstrap ClassLoader

特点：

  • 保证 Java 核心类被优先加载（比如你写一个 java.lang.String，不会被加载）
  • 有助于类隔离和安全沙箱

你也可以手动破坏双亲委派机制（如 SPI 机制中会自定义加载器绕过），但要小心内存泄漏和安全问题。

5.2 用户自定义类加载器

Java 允许开发者继承 ClassLoader 创建自己的类加载器。

用途：

  • 热部署 / 动态模块加载（如 Tomcat、OSGi）
  • 加载加密的 class 文件
  • 实现类隔离（如插件系统）

例子：

public class MyClassLoader extends ClassLoader {
    @Override
    protected Class<?> findClass(String name) throws ClassNotFoundException {
        // 自定义加载逻辑，比如从字节数组、网络中读取
    }
}
