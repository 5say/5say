在刚接触面向对象的时候，总能遇到一个概念，多态，那时候还懵懵懂懂，只记得它是面向对象的三大特性之一，干嘛用的？不知道！什么意思？不清楚！怎么用？重写，重载！

后来在工作中，突然发现多态不愧是面向对象的三大特性，有对象就有多态，复杂点的业务就要用，到后来甚至了解到它的多态甚至还有编译时多态，运行时多态，真的是被玩成花了。

所以趁着这个机会，再重新学习了解一下这个一直迷迷糊糊的概念。

一、什么是多态？

定义： 同一个引用，在不同时刻可以指向不同的子类对象，调用方法时表现不同的行为。

单看定义的时候，看的云里雾里，这些字都认识，但是连在一起想表达什么意思呢？

在这里，我们要关注几个要点

  • 同一个引用
  • 不同时刻
  • 不同的子类对象
  • 调用方法
  • 不同的行为

可以说是字字珠玑，没有废话。

首先，强调是同一个引用。

我们都知道，在 Java 程序中，想要创建一个引用，就要先声明一个对象，然后在计算机的内存中开辟一个空间，这个空间中存储的就是引用的对象的地址，所以这个对象就成为了一个引用的对象。

之后==在不同时刻可以指向不同的子类对象==。

这里有两点要注意：

  1. 首先是在不同的时刻，因为随着程序的运行，引用对象所指向的对象是可以发生改变的。只需要我们在程序中调整引用对象所引用的具体的对象，即可达到这样的目的。

  2. 其次引用对象指向了不同的子类对象，为什么要强调是子类对象呢？因为在Java程序中，一个引用对象只能指向一个类（父类）以及这个类的子类，而子类继承父类以后是可以重写父类方法的，这样同样的一个方法就有了不同的表现形式。而引用对象在调用相同的方法的时候，虽然方法名是相同的，但是方法的实现逻辑是不同的，那么方法的执行效果也是不同的，从而实现了多态。

最后==调用方法时表现不同的行为==，也就很好理解了。

小思考：

  • 为什么不能在同一时刻呢？

    因为同一时刻，一个引用对象只能指向一个它所引用的对象。

  • 为什么一定要不同的子类呢？相同的子类可以吗？

    相同的子类是不行的，因为相同的子类意味着他们的方法的逻辑没有改变，那么程序无论走多少次，都不会有不同的结果，从而无法实现多态

  • 如果我在子类的方法中调用了另一个实现了多态的类，从而使得同一个方法运行结果不同，那么我能不能说我的类也实现了多态？

    public class Polymorphism {
    public static void main(String[] args) {
        // 通过随机数，随机给B一个具体的对象，模拟B的多态在执行过程中的切换
        B b = new java.util.Random().nextBoolean() ? new B1() : new B2();
        b.method();
    }
}

class B{
    public void method(){
        System.out.println("B执行了method");
    }
}

class B1 extends B{
    @Override
    public void method(){
        System.out.println("子类B1执行了method");
    }
}

class B2 extends B{
    @Override
    public void method(){
        System.out.println("子类B2执行了method");
    }
}

    不能！因为在这样的方法中，虽然说结果不同，但我在这里提到的结果指的并不是一个具体的结果，方式方法执行逻辑的结果，比如说，我有一个方法main()，在方法main()中执行了实现了多态的类B的方法method()，虽然每次执行method()方法的时候结果都不同导致我的方法main()的结果也不同，但是对于方法main()来说，无论执行方法method()得到的结果是什么，都是在方法main()中调用方法method()的结果，并不影响方法main()的逻辑,所以还是没有实现多态。

二、实现多态的三种主要方式

2.1 方法重载 - 编译时多态 

public class Calculator {
    public int add(int a, int b) { return a + b; }
    public double add(double a, double b) { return a + b; }
}

编译器根据参数类型决定调用哪个方法。

2.2 方法重写 - 运行时多态 

class Animal {
    void sound() { System.out.println("Animal sound"); }
}

class Dog extends Animal {
    @Override
    void sound() { System.out.println("Dog barks"); }
}

虚方法表机制，运行时动态绑定到子类方法。

2.3 接口或抽象类多实现 - 运行时多态 

interface Shape {
    double area();
}

class Circle implements Shape {
    public double area() { return Math.PI * 3 * 3; }
}

class Square implements Shape {
    public double area() { return 4 * 4; }
}


Shape s = new Circle();
System.out.println(s.area()); // Circle 的面积

多个实现类通过统一接口暴露行为，是最常见的面向接口编程手段。

三、从设计层面实现多态

3.1 策略模式（Strategy Pattern） 

interface SortStrategy {
    void sort(List<Integer> list); 
}

class QuickSort implements SortStrategy { 
    public void sort(List<Integer> list) {...} 
}
class BubbleSort implements SortStrategy { 
    public void sort(List<Integer> list) {...} 
}

不同策略实现同一接口，运行时动态选择。

3.2 模板方法模式（Template Method） 

abstract class Task {
    final void execute() {
        step1(); 
        step2(); 
        step3();
    }
    abstract void step2();
}

父类定义流程骨架，子类实现步骤。

四、总结

实现方式 类型 特征与说明
方法重载 编译时多态 方法签名不同，编译期绑定
方法重写 运行时多态 子类重写父类方法，运行期根据对象类型决定绑定方法
接口/抽象类实现 运行时多态 父类/接口类型引用调用子类/实现类方法
策略模式 设计模式 利用接口 + 动态注入对象来切换行为
模板方法模式 设计模式 父类定义流程结构，子类定制部分流程
