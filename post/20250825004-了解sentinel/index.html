Sentinel 是 阿里巴巴开源的流量防卫兵，在 Spring Cloud Alibaba 体系里非常常用，主要解决 流量控制、熔断降级、系统保护 等问题。可以理解成 服务稳定性的核心工具。我给你从几个角度讲清楚：

🔹 一、 Sentinel 是什么？

Sentinel 全名 分布式流量防卫系统，2018 年阿里开源，目标是处理分布式系统下的各种稳定性问题。 它的定位有点像 Hystrix（熔断器） + RateLimiter（限流器） 的结合，但功能更强大。

主要特性：

  1. 流量控制：QPS 限流、线程数限流、预热限流、匀速排队。
  2. 熔断降级：服务调用失败率过高/响应时间过长时自动熔断。
  3. 系统保护：根据整体系统 Load、CPU 使用率进行自适应保护。
  4. 实时监控：提供 Dashboard 控制台，动态配置规则。
  5. 多维度扩展：支持注解、API、自定义规则加载（文件、Nacos、Apollo）。

🔹 二、在 Spring Cloud 中怎么用？

✅ 引入依赖 

<dependency>
    <groupId>com.alibaba.cloud</groupId>
    <artifactId>spring-cloud-starter-alibaba-sentinel</artifactId>
</dependency>

✅ 基本配置

application.yml 示例：

spring:
  cloud:
    sentinel:
      transport:
        dashboard: localhost:8858  # Sentinel 控制台地址
        port: 8719                # 客户端与 Dashboard 通信端口

启动 Sentinel Dashboard：

java -Dserver.port=8858 -Dcsp.sentinel.dashboard.server=localhost:8858 -jar sentinel-dashboard.jar

🔹 三、使用方式

① 注解方式

通过 @SentinelResource 标记需要保护的方法。

@RestController
public class OrderController {

    @GetMapping("/order")
    @SentinelResource(value = "orderResource", 
                      blockHandler = "handleBlock", 
                      fallback = "fallback")
    public String createOrder() {
        return "订单创建成功！";
    }

    // 限流时走这里
    public String handleBlock(BlockException ex) {
        return "请求过多，请稍后再试";
    }

    // 异常降级走这里
    public String fallback(Throwable t) {
        return "服务暂时不可用，请稍后重试";
    }
}

② API 配置规则（代码里写规则） 

@PostConstruct
public void initRules() {
    List<FlowRule> rules = new ArrayList<>();
    FlowRule rule = new FlowRule();
    rule.setResource("orderResource");
    rule.setGrade(RuleConstant.FLOW_GRADE_QPS);
    rule.setCount(5); // 每秒最多 5 次
    rules.add(rule);
    FlowRuleManager.loadRules(rules);
}

③ 控制台动态配置

  • 访问 http://localhost:8858/
  • 选择服务，添加规则（流控、降级、热点参数限流等）。
  • 支持接入 Nacos / Apollo，规则动态下发，不用重启。

🔹 四、Sentinel 常见规则

  1. 流控规则（FlowRule）
    • QPS 限流
    • 并发线程数限制
    • 预热模式（WarmUp，冷启动时逐渐放量）
    • 匀速排队（RateLimiter）
  2. 熔断降级规则（DegradeRule）
    • 平均响应时间超阈值
    • 异常比例超阈值
    • 异常数超阈值
  3. 系统保护规则（SystemRule）
    • Load 限制
    • CPU 使用率限制
    • 全局 QPS 限制
  4. 热点参数限流（ParamFlowRule）
    • 对某个接口的参数进行限流，比如 /user/{id}，热门 id 会被限制。

🔹 五、和 Spring Cloud Gateway、Feign 的结合

  • Feign：结合 Sentinel 做熔断和降级（替代 Hystrix）。
  • Gateway：结合 Sentinel 做限流（比 Gateway 内置的限流更强大）。

5.1 引入依赖

在 微服务（例如订单服务） 中加入依赖：

<dependency>
    <groupId>com.alibaba.cloud</groupId>
    <artifactId>spring-cloud-starter-alibaba-sentinel</artifactId>
</dependency>

如果要和 Feign、Gateway 一起用，还需要加：

<!-- Sentinel 适配 Feign -->
<dependency>
    <groupId>com.alibaba.cloud</groupId>
    <artifactId>spring-cloud-starter-alibaba-sentinel</artifactId>
</dependency>

<!-- Sentinel 适配 Gateway -->
<dependency>
    <groupId>com.alibaba.cloud</groupId>
    <artifactId>spring-cloud-alibaba-sentinel-gateway</artifactId>
</dependency>

5.2 基本配置

在每个服务的 application.yml 中配置 Sentinel：

spring:
  application:
    name: order-service
  cloud:
    sentinel:
      transport:
        dashboard: localhost:8858  # Sentinel 控制台地址
        port: 8719                # 服务和控制台的通信端口
      datasource:                 # 可选：用 Nacos 持久化规则
        ds1:
          nacos:
            server-addr: 127.0.0.1:8848
            data-id: ${spring.application.name}-sentinel
            group-id: DEFAULT_GROUP
            data-type: json
            rule-type: flow

⚡ 默认情况下，Sentinel 的规则存在内存里，重启就丢；结合 Nacos 或 Apollo 能实现持久化动态配置。

5.3 启动 Sentinel Dashboard

下载 Dashboard 包：

java -Dserver.port=8858 -Dcsp.sentinel.dashboard.server=localhost:8858 -jar sentinel-dashboard.jar

访问：http://localhost:8858

5.4 在代码中使用 Sentinel

✅ 注解方式 

@RestController
public class OrderController {

    @GetMapping("/order")
    @SentinelResource(value = "getOrder", 
                      blockHandler = "handleBlock", 
                      fallback = "handleFallback")
    public String getOrder() {
        return "订单信息";
    }

    // 限流或熔断时调用
    public String handleBlock(BlockException e) {
        return "请求过多，请稍后再试";
    }

    // 异常时调用
    public String handleFallback(Throwable t) {
        return "服务暂时不可用";
    }
}

✅ API 方式 

@PostConstruct
public void initFlowRules() {
    List<FlowRule> rules = new ArrayList<>();
    FlowRule rule = new FlowRule();
    rule.setResource("getOrder");
    rule.setGrade(RuleConstant.FLOW_GRADE_QPS);
    rule.setCount(10); // 每秒最多 10 个请求
    rules.add(rule);
    FlowRuleManager.loadRules(rules);
}

5.5 Sentinel + Feign

在 Feign 客户端开启 Sentinel 支持：

feign:
  sentinel:
    enabled: true

定义 Feign 接口：

@FeignClient(name = "user-service", fallback = UserClientFallback.class)
public interface UserClient {
    @GetMapping("/user/{id}")
    String getUser(@PathVariable("id") Long id);
}

降级处理类：

@Component
public class UserClientFallback implements UserClient {
    @Override
    public String getUser(Long id) {
        return "用户服务不可用";
    }
}

5.6 Sentinel + Gateway

在 Gateway 服务 中引入依赖（上面已写）。 配置 application.yml：

spring:
  cloud:
    gateway:
      routes:
        - id: order_route
          uri: lb://order-service
          predicates:
            - Path=/order/**
    sentinel:
      datasource:
        ds1:
          nacos:
            server-addr: 127.0.0.1:8848
            data-id: gateway-sentinel-rules
            group-id: DEFAULT_GROUP
            data-type: json
            rule-type: gw-flow

规则可在 Dashboard 中配置：

  • API 分组限流（按路径分组，比如 /order/**）
  • Route 维度限流（按路由 id）

🔹 总结

👉 Sentinel = 全能流量保护神器

  • 提供 限流（QPS / 并发）
  • 提供 熔断（RT / 异常率 / 异常数）
  • 提供 系统保护（Load / CPU）
  • 提供 热点参数限流
  • 通过 注解 / API / 控制台 / 动态配置 来使用。
