Spring Cloud Gateway这是 Spring Cloud 体系里非常重要的一个组件。

🔹 一、Spring Cloud Gateway 是什么

Spring Cloud Gateway 是 Spring 官方推出的新一代网关组件，用来替代 Zuul。

👉 它的定位：

  • 统一入口：所有请求先经过 Gateway，再路由到具体微服务。
  • 功能：路由、负载均衡、权限校验、限流、熔断、日志监控、CORS。
  • 底层基于 WebFlux（Reactor 模型），比 Zuul（Servlet 阻塞 IO）性能更好。

一句话： Spring Cloud Gateway = 高性能的 API 网关，负责请求转发和统一治理。

🔹 二、Spring Cloud Gateway 怎么用

1. 引入依赖 

<dependency>
  <groupId>org.springframework.cloud</groupId>
  <artifactId>spring-cloud-starter-gateway</artifactId>
</dependency>

2. 在 application.yml 里配置路由 

spring:
  cloud:
    gateway:
      routes:
        - id: user-service
          uri: lb://user-service     # lb:// 表示从注册中心找服务（Nacos/Eureka）
          predicates:
            - Path=/user/**          # 路由条件：匹配 /user 开头的路径
          filters:
            - StripPrefix=1          # 去掉前缀 /user

这样，访问 http://localhost:8080/user/info → Gateway → user-service 服务的 /info。

🔹 三、常用配置 

spring:
  application:
    name: gateway-service

  cloud:
    gateway:
      # ========= 1. 服务发现配置 =========
      discovery:
        locator:
          enabled: true                   # 开启服务注册中心自动路由（Nacos/Eureka）
          lower-case-service-id: true     # 服务名小写映射

      # ========= 2. 路由配置 =========
      routes:
        # ========== 路由到 user-service ==========
        - id: user-service-route          # 路由唯一 ID
          uri: lb://user-service          # 路由目标（lb:// 表示注册中心负载均衡）
          predicates:
            - Path=/user/**               # 路径匹配
            - Method=GET,POST             # 请求方法匹配
          filters:
            - StripPrefix=1               # 去掉前缀 /user
            - AddRequestHeader=X-Gateway, SpringCloud
            - AddResponseHeader=X-Response, GatewayProcessed

        # ========== 路由到 order-service ==========
        - id: order-service-route
          uri: lb://order-service
          predicates:
            - Path=/order/**
            - Header=X-Version, v1
          filters:
            - RewritePath=/order/(?<segment>.*), /${segment}   # 重写路径
            - RequestRateLimiter=1, 5                          # 限流配置（自定义 Bean）

      # ========= 3. 全局过滤器配置 =========
      default-filters:
        - AddRequestHeader=X-Request-Id, 123456   # 所有请求默认加头
        - RemoveRequestHeader=Cookie              # 移除 Cookie 头

# ========= 4. 限流配置（Redis） =========
spring:
  redis:
    host: localhost
    port: 6379

# ========= 5. actuator 监控配置 =========
management:
  endpoints:
    web:
      exposure:
        include: "*"

🔹 1. 配置说明

  1. 服务发现

    discovery.locator.enabled: true
    • 自动将注册中心的服务映射为路由，访问时可直接用 http://网关地址/服务名/**。

  2. 路由（routes）

    • id：路由标识（唯一）。
    • uri：目标地址（支持 http://、https://、lb://）。
    • predicates：断言条件（Path、Method、Host、Header、Query 等）。
    • filters：路由过滤器（请求增强、限流、熔断等）。

  3. 过滤器常见用法

    • StripPrefix=1：去掉路径前缀。
    • AddRequestHeader：加请求头。
    • RewritePath：重写请求路径。
    • RequestRateLimiter：限流，需要配置 Redis。

  4. 限流配置（RequestRateLimiter）

    • 默认基于 Redis + 令牌桶算法，需要在配置类里注册 KeyResolver（限流维度，比如按 IP、按用户 ID）。
    @Bean
KeyResolver ipKeyResolver() {
    return exchange -> Mono.just(exchange.getRequest().getRemoteAddress().getHostString());
}

  5. 全局过滤器（default-filters）

    • 对所有路由生效。

🔹 四、实现原理

Spring Cloud Gateway 的核心由 三大模块组成：

  1. Route（路由）
    • 每个路由包括：id、uri（目标服务）、predicates（断言条件）、filters（过滤器）。
    • 请求先匹配路由 → 然后执行过滤器链 → 转发到目标服务。
  2. Predicate（断言工厂）
    • 判断请求是否符合路由规则，比如 Path=/user/**、Host=**.example.com、Method=GET。
    • Gateway 内置了十几个断言工厂。
  3. Filter（过滤器工厂）
    • 请求转发前后做增强处理，比如鉴权、日志、限流。
    • 内置过滤器：AddRequestHeader、StripPrefix、RewritePath、RequestRateLimiter 等。
    • 也可以写自定义过滤器。

👉 工作流程：

客户端请求 → Gateway Handler Mapping 找到 Route → Predicate 匹配 → Filter 链增强 → 转发到目标服务 → 返回响应

🔹 4.1 常用断言（Predicates）

断言工厂 作用 示例
Path 路径匹配 Path=/user/**
Host 主机名匹配 Host=**.example.com
Method 请求方法 Method=GET,POST
Header 请求头匹配 Header=X-Request-Id, \d+
Query 查询参数匹配 Query=token, abc123
After/Before 时间匹配 After=2025-08-25T12:00:00+08:00

🔹 4.2 常用过滤器（Filters）

过滤器工厂 作用 示例
AddRequestHeader 添加请求头 AddRequestHeader=X-Token, 123
RemoveRequestHeader 删除请求头 RemoveRequestHeader=Cookie
RewritePath 重写路径 RewritePath=/foo/(?<segment>.*), /${segment}
StripPrefix 去掉路径前缀 StripPrefix=1
RequestRateLimiter 限流 使用 Redis + Token Bucket
CircuitBreaker 熔断 整合 Resilience4j/Sentinel

🔹 五、常用代码

5.1 编程式配置Gateway

除了 application.yml，还可以用 Java 配置路由：

@Configuration
public class GatewayConfig {
    @Bean
    public RouteLocator customRouteLocator(RouteLocatorBuilder builder) {
        return builder.routes()
            .route("user-service", r -> r.path("/user/**")
                .filters(f -> f.stripPrefix(1)
                               .addRequestHeader("X-Gateway", "SpringCloud"))
                .uri("lb://user-service"))
            .build();
    }
}

5.2 Gateway 鉴权（Authentication / Authorization）

5.2.1 实现思路

  • 在请求进入网关时，先判断是否携带 合法 token / session / key。
  • 通常通过 自定义全局过滤器（GlobalFilter）实现。

5.2.2 配置示例（仅路由鉴权） 

spring:
  cloud:
    gateway:
      routes:
        - id: user-service
          uri: lb://user-service
          predicates:
            - Path=/user/**
          filters:
            - StripPrefix=1

5.2.3 代码示例（JWT 鉴权） 

@Component
public class AuthFilter implements GlobalFilter, Ordered {

    @Override
    public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) {
        String token = exchange.getRequest().getHeaders().getFirst("Authorization");

        if (token == null || !isValidToken(token)) {
            exchange.getResponse().setStatusCode(HttpStatus.UNAUTHORIZED);
            return exchange.getResponse().setComplete();
        }

        return chain.filter(exchange);
    }

    private boolean isValidToken(String token) {
        // 校验 JWT 或数据库里的 token
        return token.startsWith("Bearer ");
    }

    @Override
    public int getOrder() {
        return -1; // 优先级最高
    }
}

👉 实际开发中，可以用 Spring Security + OAuth2 做更完善的鉴权。

5.3 Gateway 限流（Rate Limiting）

5.3.1 实现思路

  • Gateway 内置了 RequestRateLimiter 过滤器，基于 Redis + 令牌桶算法。
  • 需要自定义一个 KeyResolver（决定限流的维度：按 IP、按用户 ID、按路径等）。

5.3.2 配置示例 

spring:
  cloud:
    gateway:
      routes:
        - id: order-service
          uri: lb://order-service
          predicates:
            - Path=/order/**
          filters:
            - name: RequestRateLimiter
              args:
                key-resolver: "#{@ipKeyResolver}"
                redis-rate-limiter.replenishRate: 5   # 每秒放入令牌
                redis-rate-limiter.burstCapacity: 10 # 最大突发请求数

5.3.3 KeyResolver 代码 

@Bean
KeyResolver ipKeyResolver() {
    return exchange -> Mono.just(
        exchange.getRequest().getRemoteAddress().getHostString()
    );
}

👉 这样，每个 IP 每秒最多 5 个请求，突发最多 10 个。

5.3 Gateway 熔断（Circuit Breaker）

5.3.1 实现思路

  • Gateway 内置 CircuitBreaker 过滤器（底层基于 Resilience4j）。
  • 当下游服务异常 / 超时时，网关快速失败，返回默认响应。

5.3.2 配置示例 

spring:
  cloud:
    gateway:
      routes:
        - id: product-service
          uri: lb://product-service
          predicates:
            - Path=/product/**
          filters:
            - name: CircuitBreaker
              args:
                name: productCircuitBreaker
                fallbackUri: forward:/fallback/product

5.3.3 Fallback Controller 

@RestController
public class FallbackController {

    @RequestMapping("/fallback/product")
    public Map<String, String> fallback() {
        return Map.of("message", "Product service is unavailable, please try later.");
    }
}

👉 当 product-service 宕机或超时时，直接返回 降级响应。

🔹 总结对比

功能 用途 实现方式
鉴权 判断请求是否合法（token/JWT/权限） 自定义 GlobalFilter 或 Spring Security
限流 防止接口被刷、保护服务 RequestRateLimiter + Redis + KeyResolver
熔断 下游服务异常时快速失败，保证可用性 CircuitBreaker + fallback 路由

✅ 这三个功能通常是 组合使用 的：

  1. 鉴权：先拦截非法请求。
  2. 限流：防止流量过大冲击下游。
  3. 熔断：兜底保护，服务挂了还能优雅降级。

🔹 六、常用场景

  • 统一鉴权：拦截请求，校验 JWT/Token。
  • 流量控制：用 RequestRateLimiter + Redis 做限流。
  • 熔断降级：结合 Sentinel/Resilience4j。
  • 灰度发布：通过自定义路由规则按条件转发（用户、版本、IP）。
  • 日志审计：在全局过滤器中记录请求日志。

🔹 七、总结

  • Spring Cloud Gateway 是微服务网关，负责 路由转发 + 统一治理。
  • 核心组成：Route、Predicate、Filter。
  • 常用断言：Path、Host、Method、Header、Query。
  • 常用过滤器：AddRequestHeader、RewritePath、RequestRateLimiter、CircuitBreaker。
  • 扩展能力：支持自定义过滤器，能结合 Nacos、Sentinel、OAuth2 等实现复杂功能。

👉 一句话： **Spring Cloud Gateway 就是微服务大门口的保安 + 调度员，所有请求都得先过它。
