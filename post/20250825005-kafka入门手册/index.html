编程中间件面试

Kafka是微服务、高并发系统中常用的消息中间件，很多人一开始只知道它“能发消息、能解耦”，但实际上 Kafka 的设计思想、架构原理和使用场景很有深度。

📌 一、Kafka 是什么

Apache Kafka 是一个 分布式流处理平台，本质上是一个高吞吐量、低延迟的消息队列系统。 它可以用来：

  1. 消息队列（MQ）：服务解耦、削峰填谷。
  2. 日志收集：统一采集服务日志。
  3. 流式计算：结合 Kafka Streams 或 Flink，实时处理数据流。
  4. 事件驱动架构：各微服务通过事件（消息）来协作。

Kafka 的特点：

  • 高吞吐（百万级 QPS）
  • 高可用（分区副本 + ISR 机制）
  • 可持久化（消息存储在磁盘）
  • 可扩展（分布式架构，Topic/Partition）

📌 二、Kafka 核心概念

  1. Producer（生产者）
    • 负责发送消息到 Kafka。支持异步发送、批量发送，提高吞吐量。
    • 可以指定发送到哪个 Topic，并且可根据 key 决定落到哪个 Partition。
  2. Consumer（消费者）
    • 从 Kafka 拉取消息。
    • 消费 Topic 消息，多个消费者组成 Consumer Group。
    • 同一组内每条消息只会被一个消费者消费，实现负载均衡。
    • Kafka offset 用于记录消费进度，可手动或自动提交。
  3. Broker（代理）
    • Kafka 集群中的节点，每个 Broker 存储部分数据。
  4. Topic（主题）
    • 消息按主题分类，比如 order_topic、user_topic。
    • 一个 Topic 可以划分多个 Partition，每个 Partition 是有序的消息队列。
  5. Partition（分区）
    • Kafka 的并行单位，提供高吞吐。
    • 一个 Topic 下可以有多个 Partition（分区）。
    • 同一个 Topic 的数据会被分散到不同 Partition，提高并发能力。
    • 同一分区内消息有序，但跨分区无序。
    • 分区可以有多个副本（Replication），Leader 副本负责读写，Follower 做备份。
  6. Offset（偏移量）
    • 消费者消费的进度。
    • Kafka 会记录 offset，支持“断点续传”。
  7. 副本机制（Replication）
    • 每个 Partition 有多个副本（leader + follower）。
    • Leader 负责读写，Follower 负责备份。
    • 如果 Leader 挂了，Follower 会选举为新 Leader。
  8. Broker（服务器）
    1. Kafka 集群中的节点，每个 Broker 管理一部分 Topic 的 Partition。
    2. 集群中通过 Leader/Follower 副本机制保证高可用。

📌 三、Kafka 架构

👉 生产者 → Broker（存储到分区日志） → 消费者

简单流程：

  1. Producer 将消息发送到某个 Topic 的 Partition。
  2. Broker 接收消息，顺序写入日志文件（磁盘 + PageCache）。
  3. Consumer Group 中的消费者读取消息，并提交 Offset。
  4. Kafka 通过 Zookeeper（早期）或 KRaft（新版本自带）管理集群、选举 leader。

3.1 Kafka 消息存储机制

Kafka 的高性能关键在于 顺序写 + 零拷贝 + 索引 + 分段日志。

  1. 顺序写
    • Kafka 将消息追加写入 Partition 对应的 日志文件（commit log）。
    • 顺序写比随机写快很多，利用操作系统 PageCache。
  2. 分段日志（Segment）
    • Partition 的日志分成多个 segment 文件。
    • 旧日志可删除或归档（通过 retention 配置控制）。
  3. 索引（Offset Index）
    • Kafka 用索引文件快速定位消息偏移量。
    • 消费者通过 offset 拉取消息，不需要遍历整个日志。
  4. 零拷贝机制
    • 消息直接从 PageCache 传给网络 Socket，减少内存复制，提高吞吐。

3.2 消费机制（Consumer）

  1. Pull 模型
    • 消费者主动拉取消息，而不是 Broker 推送。
    • 可以控制拉取速率，削峰填谷。
  2. Consumer Group
    • 同一组内每条消息只被消费一次。
    • 如果组内有多个消费者，Partition 会自动均衡分配。
  3. Offset 管理
    • 每条消息在 Partition 中有唯一 offset。
    • 消费者可以：
      • 自动提交 offset
      • 手动提交 offset
      • 从特定 offset 开始消费（断点续传）

3.2.1 顺序消费（Partition 内消息有序） 

@KafkaListener(topics = "user_click_topic", groupId = "click_group")
public void listenUserClicks(String message, @Header(KafkaHeaders.RECEIVED_PARTITION_ID) int partition) {
    System.out.println("Partition " + partition + " 消费消息：" + message);
}

特点：

  • Kafka 同一分区内消息顺序消费。
  • 可以通过 key 分区保证同一用户事件在同一 Partition。
kafkaTemplate.send("user_click_topic", userId, message); // key=userId

3.2.2 消费者组（负载均衡） 

@KafkaListener(topics = "order_topic", groupId = "inventory_group")
public void listenOrders(String orderMessage) {
    System.out.println("消费者处理订单：" + orderMessage);
}

特点：

  • 多个实例同属一个组，消息均匀分配。
  • 保证每条消息只被组内一个消费者消费。

3.2.3 Offset 管理（断点续传） 

@KafkaListener(topics = "task_topic", groupId = "task_group")
public void listenTask(ConsumerRecord<String, String> record, Acknowledgment ack) {
    try {
        System.out.println("处理任务：" + record.value());
        // 手动提交 offset
        ack.acknowledge();
    } catch (Exception e) {
        // 消费失败，可重试或跳过
    }
}

3.3 高可用与可靠性

  1. 副本机制（Replication）
    • Partition 有多个副本（默认 1 个 Leader + N 个 Follower）。
    • Leader 负责读写，Follower 异步复制。
  2. ISR（In-Sync Replicas）
    • 同步副本集合，保证消息写入至少同步到 ISR 才算成功。
    • Leader 挂掉时，从 ISR 中选出新的 Leader。
  3. ACK 策略
    • acks=0：生产者不等待，最快，但可能丢消息
    • acks=1：Leader 写入成功即返回
    • acks=all：所有 ISR 写入成功才返回，保证强一致性

3.3.1 高可用（副本 + ACK 策略） 

spring:
  kafka:
    producer:
      bootstrap-servers: localhost:9092
      key-serializer: org.apache.kafka.common.serialization.StringSerializer
      value-serializer: org.apache.kafka.common.serialization.StringSerializer
      acks: all   # Leader + ISR 全部写入才算成功

特点：

  • 副本机制保证 Broker 挂掉不丢消息。
  • acks=all 确保高可靠性。

3.3.2 可靠性（ACK + ISR + 重试） 

kafkaTemplate.send("payment_topic", message)
    .addCallback(
        result -> System.out.println("支付消息发送成功"),
        ex -> System.err.println("支付消息发送失败，重试中...")
    );

特点：

  • 配合 acks=all + ISR + Producer 重试保证消息可靠送达。

3.4 高吞吐和扩展原理

  1. 分区并行
    • Topic 分多个 Partition，生产者和消费者可并行处理不同分区，吞吐几乎线性扩展。
  2. 批量发送与压缩
    • Producer 支持批量发送消息，减少网络请求。
    • 支持 GZIP/Snappy/LZ4 压缩，提高网络和存储效率。
  3. 异步复制
    • Follower 异步拉取 Leader 的消息，提高写入吞吐。
  4. 无中心化消费
    • Consumer 通过拉取和 offset 自管理，不依赖 Broker 主动推送，减少 Broker 压力。
@Autowired
private KafkaTemplate<String, String> kafkaTemplate;

public void sendBatchMessages(List<String> messages) {
    messages.forEach(msg -> 
        kafkaTemplate.send("order_topic", msg)
            .addCallback(
                success -> System.out.println("发送成功：" + success.getRecordMetadata()),
                failure -> System.err.println("发送失败：" + failure.getMessage())
            )
    );
}

特点：

  • 异步发送，提高吞吐量。
  • 可以批量发送消息，减少网络请求。

3.5 Kafka 核心设计总结

设计点 原理 / 优势
顺序写日志 磁盘 IO 高效，低延迟
分段 + 索引 快速定位消息，支持大数据量
Pull 消费模型 消费者自控速率，削峰填谷
Partition 并行 高吞吐、可水平扩展
ISR 副本机制 高可用、高可靠
ACK 策略 可调一致性和性能
零拷贝 减少内存拷贝，提高性能

✅ 总结一句话： Kafka 的核心原理就是“顺序写 + 分区并行 + 副本同步 + 拉取消费 + offset 管理”，在保证高吞吐的同时又保证可靠性和可扩展性”。

📌 四、Kafka 的优势

  1. 高性能：利用磁盘顺序写 + PageCache，性能比传统 MQ 高。
  2. 可扩展：通过增加 Partition 和 Broker 实现水平扩展。
  3. 高可用：多副本 + Leader 选举。
  4. 强大的消费模型：
    • 点对点（一个消息给一个消费者）
    • 发布订阅（多个 Consumer Group 各自独立消费）

📌 五、Kafka 的典型使用场景

  1. 日志收集系统：ELK（Elasticsearch + Logstash + Kafka）
  2. 电商订单系统：下单消息写入 Kafka，后续由库存、支付、物流等消费。
  3. 流量削峰：高峰时 Kafka 临时存储请求，后台服务按能力消费。
  4. 实时大数据处理：Kafka + Flink 实时统计 UV、PV、交易量等。

📌 六、Kafka 在 Spring Cloud 中的使用

Spring Cloud Stream 提供了对 Kafka 的封装，使用起来非常方便：

  1. 引入依赖
<dependency>
    <groupId>org.springframework.cloud</groupId>
    <artifactId>spring-cloud-starter-stream-kafka</artifactId>
</dependency>
  1. 配置文件
spring:
  cloud:
    stream:
      default-binder: kafka
      bindings:
        output:   # 生产者
          destination: order-topic
        input:    # 消费者
          destination: order-topic
          group: order-service-group
      kafka:
        binder:
          brokers: localhost:9092
  1. 代码示例
@EnableBinding({Source.class, Sink.class})
public class OrderMessageService {

    @Autowired
    private MessageChannel output;

    // 生产消息
    public void sendMessage(String msg) {
        output.send(MessageBuilder.withPayload(msg).build());
    }

    // 消费消息
    @StreamListener(Sink.INPUT)
    public void receiveMessage(String msg) {
        System.out.println("收到消息：" + msg);
    }
}

📌 七、和其他 MQ 的对比

特性 Kafka RabbitMQ RocketMQ
性能 百万级 QPS 万级 QPS 十万级 QPS
消息顺序 分区内有序 队列内有序 队列内有序
事务消息 弱支持（幂等处理） 支持事务消息 强支持事务消息
延时消息 需结合定时任务实现 支持 支持（更强大）
使用场景 大数据、日志、流计算 普通业务解耦 金融、电商
