Nacos 在 Spring Cloud 体系里用得非常多，我们可以从 它的定位 → 使用方式 → 实现原理 三个角度来理解。

🔹 一、Nacos 是干嘛的

Nacos 全称是 Dynamic Naming and Configuration Service，是阿里开源的一体化服务平台，主要提供两个核心能力：

  1. 服务注册与发现（替代 Eureka、Consul、Zookeeper）
    • 微服务启动时，把自己信息（IP、端口、健康状态、元数据）注册到 Nacos。
    • 其他服务通过 Nacos 找到目标服务地址，完成调用。
    • 支持临时实例（宕机即剔除）和永久实例（需要人工下线）。
  2. 配置管理（替代 Spring Cloud Config、Apollo 等）
    • 把项目中的配置文件（application.yml 等）集中放在 Nacos。
    • 应用启动时从 Nacos 拉取配置，并支持 实时动态刷新。
    • 配置支持多环境、多租户隔离（Namespace、Group、DataId）。

👉 所以一句话总结： Nacos = 注册中心 + 配置中心 + 一些额外能力（DNS、元数据管理、动态权重路由等）。

🔹 二、Nacos 怎么使用

以 Spring Cloud Alibaba 为例，常见步骤：

1. 安装 Nacos 

# 下载并启动
sh startup.sh -m standalone

默认启动在 8848 端口。访问 http://localhost:8848/nacos，默认账号/密码：nacos / nacos。

2. 服务注册与发现

在微服务 A（provider）中：

<!-- pom.xml -->
<dependency>
  <groupId>com.alibaba.cloud</groupId>
  <artifactId>spring-cloud-starter-alibaba-nacos-discovery</artifactId>
</dependency>
# application.yml
spring:
  application:
    name: service-provider   # 服务名
  cloud:
    nacos:
      discovery:
        server-addr: localhost:8848

在微服务 B（consumer）中调用：

@FeignClient("service-provider")
public interface ProviderClient {
    @GetMapping("/hello")
    String hello();
}

这样 B 就能通过服务名 service-provider 找到 A 的地址，不需要硬编码 IP。

3. 配置中心

在 Nacos 控制台新建配置：

  • DataId: service-provider-dev.yaml
  • Group: DEFAULT_GROUP
  • 内容：
user:
  name: ZhangSan
  age: 18

在服务中读取配置：

<dependency>
  <groupId>com.alibaba.cloud</groupId>
  <artifactId>spring-cloud-starter-alibaba-nacos-config</artifactId>
</dependency>
spring:
  application:
    name: service-provider
  profiles:
    active: dev
  cloud:
    nacos:
      config:
        server-addr: localhost:8848
        file-extension: yaml
@RestController
@RefreshScope
public class ConfigController {
    @Value("${user.name}")
    private String name;

    @GetMapping("/user")
    public String getUser() {
        return name;
    }
}

当你在 Nacos 修改配置并发布，服务就会 自动刷新 配置。

4. Nacos常用注解与方法

好嘞 👍 你想要更落地的用法，我来在前面的内容基础上补充 常用注解、常用配置、常用方法，这样更接近真实开发场景。

4.1 常用的 Nacos 注解

在 Spring Cloud Alibaba 中，Nacos 和 Spring Boot 紧密集成，常用注解主要有：

  1. @EnableDiscoveryClient

    • 开启服务注册与发现功能（其实 spring-cloud-starter-alibaba-nacos-discovery 自动装配后可以省略，但显式加上更清晰）。
    @SpringBootApplication
@EnableDiscoveryClient
public class ProviderApplication {
    public static void main(String[] args) {
        SpringApplication.run(ProviderApplication.class, args);
    }
}

  2. @NacosValue（推荐少用，Spring 官方推崇 @Value）

    • 作用和 @Value 类似，但支持 自动刷新。
    @RestController
public class ConfigController {
    @NacosValue(value = "${user.name:default}", autoRefreshed = true)
    private String userName;

    @GetMapping("/name")
    public String name() {
        return userName;
    }
}

  3. @RefreshScope

    • Spring Cloud 提供的，放在类上，表示这个类里的配置可以在不重启服务的情况下动态刷新。
    @RestController
@RefreshScope
public class ConfigController {
    @Value("${user.age}")
    private int age;
}

  4. @NacosInjected

    • 可以注入 Nacos 的 NamingService 客户端对象，用于编程式操作。
    @RestController
public class TestController {
    @NacosInjected
    private NamingService namingService;
}

4.2 常用的 Nacos 配置

在 application.yml 或 bootstrap.yml 里，常见的配置分为 服务注册 和 配置中心 两类。

4.2.1 服务注册发现配置 

spring:
  application:
    name: service-provider  # 服务名
  cloud:
    nacos:
      discovery:
        server-addr: 127.0.0.1:8848
        namespace: dev-namespace-id   # 环境隔离
        group: DEV_GROUP              # 服务分组
        ephemeral: true               # 是否临时实例（默认 true）
        weight: 2                     # 负载均衡权重

4.2.2 配置中心配置 

spring:
  application:
    name: service-provider
  profiles:
    active: dev
  cloud:
    nacos:
      config:
        server-addr: 127.0.0.1:8848
        namespace: dev-namespace-id
        group: DEV_GROUP
        file-extension: yaml   # 配置文件格式
        refresh-enabled: true  # 是否允许自动刷新

👉 Nacos 配置文件三要素：

  • Namespace：环境隔离（如开发 / 测试 / 生产）。
  • Group：逻辑分组（如 DEFAULT_GROUP，或者业务分组）。
  • DataId：具体配置文件名（如 service-provider-dev.yaml）。

4.3 编程中常用的方法

有些场景下，你需要手动操作 Nacos，而不是仅靠自动注册。 Nacos 提供了 NamingService（服务注册发现） 和 ConfigService（配置管理） 两个核心 API。

4.3.1 NamingService（服务注册与发现） 

// 获取实例
NamingService namingService = NacosFactory.createNamingService("127.0.0.1:8848");

// 注册服务
namingService.registerInstance("service-provider", "127.0.0.1", 8080);

// 注销服务
namingService.deregisterInstance("service-provider", "127.0.0.1", 8080);

// 获取服务实例列表
List<Instance> instances = namingService.getAllInstances("service-provider");

// 订阅服务（监听服务变化）
namingService.subscribe("service-provider", event -> {
    System.out.println("服务变化：" + event);
});

4.3.2 ConfigService（配置管理） 

// 获取配置服务
ConfigService configService = NacosFactory.createConfigService("127.0.0.1:8848");

// 获取配置
String content = configService.getConfig("service-provider-dev.yaml", "DEFAULT_GROUP", 5000);
System.out.println(content);

// 发布配置
configService.publishConfig("test.yaml", "DEFAULT_GROUP", "name=Tom");

// 删除配置
configService.removeConfig("test.yaml", "DEFAULT_GROUP");

// 监听配置变化
configService.addListener("service-provider-dev.yaml", "DEFAULT_GROUP", new Listener() {
    @Override
    public Executor getExecutor() { return null; }

    @Override
    public void receiveConfigInfo(String configInfo) {
        System.out.println("配置变化：" + configInfo);
    }
});

🔹 三、Nacos 实现原理

  1. 服务注册与发现原理
    • 注册：服务启动时，客户端（通过 Nacos SDK）向 Nacos Server 发送 REGISTER 请求（包含 IP、端口、元数据）。
    • 心跳机制：客户端定时（默认 5s）发送心跳包，Nacos 判断实例是否健康。
    • 服务发现：消费者通过服务名向 Nacos 拉取实例列表，客户端本地维护缓存，并定时更新。
    • 一致性协议：Nacos 1.x 使用 Raft + Distro 协议 保证集群一致性，2.x 引入 gRPC 提高性能。
  2. 配置管理原理
    • 拉模式：应用启动时主动从 Nacos 拉取配置。
    • 推模式：Nacos 使用 长轮询 / gRPC 长连接 机制，当配置变更时，立即推送给客户端。
    • 分组管理：Namespace（环境隔离）、Group（逻辑分组）、DataId（具体配置文件标识）。
  3. 架构
    • Nacos Server：负责存储（默认 MySQL）、管理服务与配置。
    • Nacos Client：集成在应用中，负责注册、发现、拉取配置、监听变更。
    • 通信：1.x HTTP + 长轮询，2.x gRPC 长连接。

✅ 一句话总结： Nacos 就是一个把服务注册中心和配置中心打包在一起的中台系统，核心通过心跳和长连接实现动态服务发现与配置刷新。
