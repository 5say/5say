📌 一、Redis 是什么

Redis（REmote DIctionary Server）是一个开源的 高性能内存键值数据库，支持多种数据结构（String、Hash、List、Set、Sorted Set、Bitmap、HyperLogLog、Stream 等）。

Redis 特点：

  1. 高速：基于内存存储，读写非常快（百万级 QPS）。
  2. 丰富数据结构：不仅是简单 KV，还支持复杂数据操作。
  3. 持久化：可选 RDB 快照、AOF 日志，实现数据持久化。
  4. 单线程模型：利用事件驱动 + I/O 多路复用，避免线程切换开销。
  5. 支持分布式：Cluster 模式、主从复制、哨兵（Sentinel）高可用。
  6. 丰富功能：事务、Lua 脚本、发布/订阅、过期策略。

📌 二、Redis 核心特点与使用场景

特性 使用场景
高速 KV 存储 缓存热点数据，例如商品信息、用户会话
数据结构丰富 排行榜（Sorted Set）、计数器（String/INCR）、标签集合（Set）
过期策略 会话、验证码、临时缓存
持久化 日志系统、临时队列恢复
发布/订阅 消息通知、事件广播
Lua 脚本事务 原子操作，例如扣减库存、限流

2.1 Redis的各种数据类型以及使用场景

2.1.1 String（字符串）

特点：

  • 最简单的数据类型，存储字符串、数字等。
  • 最大 512MB。

常用操作：

  • SET key value [EX seconds] 设置值和过期时间
  • GET key 获取值
  • INCR key 自增
  • DECR key 自减

使用场景：

  1. 缓存单个对象：商品详情、用户信息
  2. 计数器：访问量 PV/UV、点赞数
  3. 分布式锁：SETNX + EX

示例：

redisTemplate.opsForValue().set("user:1:name", "Alice", 1, TimeUnit.HOURS);
redisTemplate.opsForValue().increment("page:view:123"); // PV++

2.1.2 Hash（哈希表）

特点：

  • 类似 Map，字段（field）和值（value）对存储在一个 key 下。
  • 适合存储对象结构。

常用操作：

  • HSET key field value
  • HGET key field
  • HGETALL key

使用场景：

  1. 存储对象：用户信息、商品信息
  2. 部分更新：只更新对象的某个字段，不影响其他字段
  3. 内存优化：比多个 String key 更节省空间

示例：

HashOperations<String, Object, Object> hashOps = redisTemplate.opsForHash();
hashOps.put("user:1", "name", "Alice");
hashOps.put("user:1", "age", 25);
Object age = hashOps.get("user:1", "age");

2.1.3 List（列表）

特点：

  • 有序列表，可左/右 push/pop。
  • 支持按索引访问、范围查询。

常用操作：

  • LPUSH key value 左插入
  • RPUSH key value 右插入
  • LPOP key / RPOP key 弹出
  • LRANGE key start stop 范围获取

使用场景：

  1. 消息队列：简单队列（阻塞或非阻塞）
  2. 任务列表：待处理订单、任务调度
  3. 日志列表：最近 N 条日志

示例：

redisTemplate.opsForList().rightPush("task:queue", "task1");
String task = redisTemplate.opsForList().leftPop("task:queue");

2.1.4 Set（集合）

特点：

  • 无序集合，元素唯一。
  • 支持交集、并集、差集操作。

常用操作：

  • SADD key value 添加
  • SREM key value 移除
  • SISMEMBER key value 是否存在
  • SMEMBERS key 获取所有元素

使用场景：

  1. 标签系统：用户兴趣标签、商品分类标签
  2. 去重：独立访问用户集合
  3. 好友关系：社交应用关注/粉丝列表
  4. 集合运算：交集/并集/差集

示例：

redisTemplate.opsForSet().add("user:1:tags", "java", "redis");
boolean hasTag = redisTemplate.opsForSet().isMember("user:1:tags", "java");

2.1.5 Sorted Set（有序集合）

特点：

  • 每个元素有一个 score（分数），自动按 score 排序。
  • 支持范围查询、排名。

常用操作：

  • ZADD key score value 添加
  • ZRANGE key start stop [WITHSCORES] 按排名获取
  • ZRANK key value 获取元素排名

使用场景：

  1. 排行榜：游戏分数榜、销售排行榜
  2. 延时队列：score 存储时间戳，按时间处理
  3. 带权重集合：热门文章、热门商品

示例：

redisTemplate.opsForZSet().add("game:rank", "player1", 100);
Set<Object> top10 = redisTemplate.opsForZSet().range("game:rank", 0, 9);

2.1.6 Bitmap（位图）

特点：

  • 按位存储 0/1，占用少量内存。
  • 可用于高效统计。

常用操作：

  • SETBIT key offset value
  • GETBIT key offset
  • BITCOUNT key

使用场景：

  1. 签到统计：用户每日签到记录
  2. 去重统计：大规模 UV 统计
  3. 权限开关：单个位表示某种状态

示例：

redisTemplate.opsForValue().setBit("sign:2025-08-25", 1234, true);
boolean signed = redisTemplate.opsForValue().getBit("sign:2025-08-25", 1234);

2.1.7 HyperLogLog

特点：

  • 用于统计基数（不重复元素数量），占用内存小，误差 0.81%。

常用操作：

  • PFADD key element
  • PFCOUNT key

使用场景：

  1. 独立用户统计（UV）
  2. 日志去重统计
  3. 大规模访问量统计

示例：

redisTemplate.opsForHyperLogLog().add("uv:2025-08-25", "user123");
long uv = redisTemplate.opsForHyperLogLog().size("uv:2025-08-25");

2.1.8 Stream（消息流）

特点：

  • 类似 Kafka 的日志流，按 ID 有序存储。
  • 支持消费组、阻塞消费。

常用操作：

  • XADD key * field value 添加
  • XREAD COUNT 10 STREAMS key lastId 读取
  • XGROUP CREATE key groupName $ 创建消费组

使用场景：

  1. 消息队列：延时任务、事件流处理
  2. 日志收集：服务日志、交易流水
  3. 微服务事件总线

示例：

redisTemplate.opsForStream().add("order_stream", Map.of("orderId", "12345"));

🔹 总结

数据类型 特点 使用场景
String 简单 KV 缓存对象、计数器、分布式锁
Hash 类 Map，多字段存储 用户/商品对象、部分更新
List 有序列表 队列、任务列表、日志列表
Set 无序、唯一 标签、去重、好友关系
Sorted Set 有序集合 + score 排行榜、延时队列、带权重集合
Bitmap 按位存储 签到、UV 去重、权限开关
HyperLogLog 基数统计，低内存 UV 统计、大规模去重
Stream 消息流、有序队列 消息队列、事件流、日志流

📌 三、使用 Redis 可能遇到的问题及解决方案

1️⃣ 缓存穿透（Cache Penetration）

问题：

  • 查询一个一定不存在的数据，缓存中没有，会直接请求数据库，频繁请求会打爆 DB。

解决方案：

  1. 空值缓存：如果查询结果为空，仍缓存（如 null 或特殊标识），设置短期过期。
  2. 布隆过滤器：在访问 DB 前，先判断 key 是否可能存在，快速过滤掉不存在的请求。

示例（Java + Spring Redis）：

String key = "user:" + userId;
Object user = redisTemplate.opsForValue().get(key);
if (user == null) {
    if (!bloomFilter.mightContain(userId)) {
        return null; // 直接返回
    }
    user = dbService.getUserById(userId);
    redisTemplate.opsForValue().set(key, user, 10, TimeUnit.MINUTES);
}

2️⃣ 缓存击穿（Cache Breakdown）

问题：

  • 热点数据（如商品详情）过期时，大量并发请求直接打到 DB。

解决方案：

  1. 互斥锁（Mutex Key）：只有第一个线程去 DB 查询并重建缓存，其他线程等待。
  2. 永不过期 + 定时更新：热点数据不过期，定期刷新缓存。
  3. 异步更新：用后台线程异步更新缓存，前端请求直接返回旧数据。

示例（互斥锁）：

if (redisTemplate.opsForValue().setIfAbsent("lock:product:" + id, "1", 10, TimeUnit.SECONDS)) {
    try {
        Object data = dbService.getProductById(id);
        redisTemplate.opsForValue().set("product:" + id, data, 1, TimeUnit.HOURS);
    } finally {
        redisTemplate.delete("lock:product:" + id);
    }
} else {
    Thread.sleep(50); // 等待锁释放
    return redisTemplate.opsForValue().get("product:" + id);
}

3️⃣ 缓存雪崩（Cache Avalanche）

问题：

  • 缓存大量 key 同时过期，导致瞬间请求打到 DB，DB 承受不住。

解决方案：

  1. 加随机过期时间：避免同一时间大量缓存过期。
  2. 分散缓存刷新：后台异步刷新热点数据。
  3. 双层缓存：本地 + Redis，降低瞬时压力。

示例（随机过期时间）：

int ttl = 3600 + new Random().nextInt(300); // 1小时到1小时5分钟
redisTemplate.opsForValue().set(key, value, ttl, TimeUnit.SECONDS);

4️⃣ 缓存更新问题（一致性问题）

问题：

  • DB 更新后，缓存未及时更新，可能读到旧数据。

解决方案：

  1. Cache Aside 模式（应用主动维护缓存）：
    • 先更新 DB → 删除缓存（下一次读自动刷新缓存）。
  2. 读写穿透 + 消息队列异步更新：
    • DB 更新 → 发送 MQ 消息 → 消费端更新缓存。
  3. Redis 事务 / Lua 脚本：原子更新，避免并发问题。

示例（Cache Aside）：

dbService.updateUser(user);
redisTemplate.delete("user:" + user.getId());

5️⃣ Redis 内存问题（大 key、内存泄漏）

问题：

  • 单个 key 数据量太大或大量过期未清理，占用大量内存。

解决方案：

  1. 限制 key 大小和 value 大小。
  2. 合理设置过期策略（TTL、LRU）。
  3. 分库/分表缓存，避免单 key 超大。
  4. 监控内存：INFO MEMORY、used_memory，及时扩容或清理。

🔹 总结

问题 原因 解决方案
缓存穿透 查询不存在的 key 空值缓存、布隆过滤器
缓存击穿 热点 key 过期 互斥锁、永不过期 + 定时刷新
缓存雪崩 大量缓存同时过期 随机 TTL、分散刷新、双层缓存
缓存不一致 DB 更新未同步缓存 Cache Aside、MQ 异步刷新、Lua 脚本
内存压力 大 key、大量数据或泄漏 限制 key 大小、TTL、LRU、监控内存
